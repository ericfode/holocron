# Gated JEPA WASI bot

This packages the current Arena table `jepa-tx-gate` as one WASI preview-1 module. The transformer kernels are
generated by tinygrad; Rust supplies feature encoding, checkpoint binding, resource rules, protocol and simulator
planning. The existing two checkpoints are embedded unchanged. There is no training or rules engine in the module.

The reference is `bots/jepa/js/jepa.js`, SHA-256
`1cc76a771552eb13493f7e1af1c78d13e619fc62279ef50fe3156efe81409e85`, identical to Arena's vendor at the verified
strict-v2 host revision `3afa1f8bbf3bc45a08359f15b96291d55c641fa6`. The newer Python line predictor is separate
research and is not substituted for this table bot.

## Preserved decision path

1. Encode 73 state features, 62 features per action, and ordered card tokens with 21 features and hashed IDs.
   The checkpoint truncates/pads to 24 tokens. Calculations use the JS float64-to-float32 boundary.
2. Encode the position once per checkpoint role and cache each transformer's context keys/values. Score independent
   candidates in batches of four at a selected horizon. The width-64, two-layer, four-head transformer produces a
   96-dimensional state latent and residual predicted latents, then the value head supplies logits.
3. Use the evaluator copy for imagined window/follow-up choices and the original value head for simulated leaves.
   Keep settled horizon `s`, mix 0, c-clock resourcing and gate `max(score)-min(score) >= 0.04`.
4. Above the gate, request the host simulator synchronously: up to 16 roots, follow-up widths 6/3, depth 2,
   150 lines, 5 seconds, an 80-step line cap and a 2,500 ms remaining-time margin. Roots share deal 0. The existing
   rush response handles the opponent; the controller remembers matching follow-up choices and retains the loop guard.
5. Answer with the original offered action index. Card metadata comes only from `hello.cards`.

The executable requires an offered integer protocol 2 and answers integer `ready.v=2, sim=true`, with no
`simEngine` field. `sim` requests receive `simulated` before the final `act`; `over` receives `ok`. The executable
rejects the library's historical v1 fallback. The host's default simulator selection is preserved.

## Build

The verified local recipe uses Rust 1.98, the installed `wasm32-unknown-unknown` standard library, Rust's LLVM tools
component, Apple Clang 21, `wasm-tools`, and the installed `wasm32-wasip2` self-contained `libc.a` for math functions.
It retargets unoptimized Clang IR before optimization, retaining i64 setter indices and wasm32 pointers. All host
calls are explicit WASI preview-1 imports. This is a tested build route, not a claim that arbitrary native IR is
portable or that a full WASI SDK build has been verified. No component adapter or preview-2 imports are required.
Dependencies in both Cargo lockfiles must already be available; this command uses `--offline` and downloads nothing.

```sh
python3 bots/jepa/wasm/build.py
```

Output: `build/arena/jepa_tx_gate_wasm/{bot.wasm,arena.json}`. The manifest explicitly declares integer protocol 2,
WASI preview 1, no network, entry SHA-256, source hashes and checkpoint hashes. It does not register or submit the bot.
The module has 16 MiB initial linear memory and a 256 MiB maximum. `deterministic:false` acknowledges the inherited
wall-clock search cutoff; bounded parity fixtures use fixed scripted limits. Rebuilding with the same source and
toolchain reproduces the executable; the complete bundle ID also includes its source-commit manifest provenance.

The generated C is checked in so ordinary builds need no tinygrad installation. [export/README.md](export/README.md)
pins the exporter source, documents its compatibility adapters, and gives a no-training regeneration command.
Both original checkpoint SHA-256 values are verified before every package build.

## Verification

```sh
cargo test --offline --manifest-path bots/jepa/wasm/controller/Cargo.toml
cargo build --offline --release --features diagnostics --manifest-path bots/jepa/wasm/runtime/Cargo.toml
cargo build --offline --release --features diagnostics --target wasm32-unknown-unknown --manifest-path bots/jepa/wasm/runtime/Cargo.toml
python3 bots/jepa/wasm/tests/check_runtime.py \
  --native bots/jepa/wasm/runtime/target/release/jepa-wasi \
  --wasm bots/jepa/wasm/runtime/target/wasm32-unknown-unknown/release/jepa-wasi.wasm
```

`diagnostics` enables test-only tensor/statistics messages and must not be used for the submission artifact.
Re-run `build.py` without that option to produce the normal protocol bundle. `JEPA_CONFIG` is an optional JSON
configuration for bounded comparisons; the package's environment is empty and its defaults preserve the table.

The controller suite checks bit-exact features, hash IDs, resource decisions, Python RNG and 20 scripted planner
cases. Actual-checkpoint native and WASI tests check 126 combinations per backend, seven ordinary decisions and six
simulator transcripts, including follow-ups and low-time fallback. Maximum action-logit error is about 3.12e-6 at
absolute tolerance 1e-5; best indices and scripted behavior match. See [tests/README.md](tests/README.md).

[host-evidence/README.md](host-evidence/README.md) documents the exact Arena host/checker blobs, isolated v2 exchange,
bundle digest, memory and timing evidence. Host checks use `wasmtime==49.0.0`, installed normally with pip in an
isolated environment. CLI Wasmtime 44 numerical/fuel evidence is labeled separately. The production host command
sets no fuel limit; optional fuel measures a whole decide exchange, including guest work between simulation replies.

These are synthetic implementation and host checks. They establish neither full-game strength nor timing on a live
Arena machine. The host charges aggregate wall time, including simulator waits; its live game-bank setting is
unknown here. A 5-second planner cutoff can therefore explore different counts on different machines. Tiny score
differences can also change near-ties outside these fixtures. No full games, rated admission, live submission or
checkpoint changes were performed. CPython-WASI wrapper overhead remains unmeasured: its runtime was unavailable;
ordinary host Python plus Wasmtime is a different dependency from the guest CPython-WASI executable.
