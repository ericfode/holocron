# Separate constructor-support recovery

This new crate preserves the failed v1 collector's Rust source byte for byte
(`f80e5fa4…`) and uses the distinct executable
`public-input-binding-recovery-collector`. The original executable, sources,
manifest, plan, failure receipts and charged ledger remain protected inputs.
The old environment-variable names intentionally remain because the Rust is
unchanged.

The new plan preserves all nine original complete card rows, all 16 worlds,
intents, paired comparisons and hypotheses. Its only catalogue addition is the
exact existing `TOKEN_SHIELD` row required unconditionally by the native
constructor. Its original `unsupported` status is preserved. It is constructor
support, not an experimental source or a coverage expansion. No physical Shield
is authored. The new guard checks every actual case capture's native state,
nested attachments and projection counts for zero physical Shields before
accepting collection. Catalogue metadata is excluded from that physical check.

The scientific fixtures remain LAW045 own/opponent helper factorials and LOF215
intended-host/layout controls. Raw receipt and durable journal schemas are
unchanged. Both draw piles and the opponent hand are empty; our only hand card
is the source. Pre-action public state and declared intent are predictor input;
after-state parent links are independent label proof. The frozen predictor and
independent verifier are unchanged. Full physical attachment legality,
snapshot/load, offered-action, settlement and both-anchor checks still apply.

The new accounting module links the immutable failed v1 ledger and parent
evidence. Root must freeze all inputs before any build or collection. There is
one build allocation of 30 seconds/zero applications and one collection
allocation of 60 seconds/80 applications, at most five per root. No automatic
retry or credit exists. Failed collection charges its full reservation while
observed applications remain separately journal-derived or unknown. An
uncertain owned-process cleanup leaves the attempt pending.

The guard retains the audited concurrent live owned-process RSS check at 1 GiB,
50 ms sampling and parent-plus-largest-child rusage supplement. Historical PID
peaks are metadata only. One Cargo job and numerical thread limits are used;
there is no OS core-affinity or memory-reservation claim. It uses the existing
warm task7 cache, offline locked dependencies and the previous debug0,
nonincremental compiler profile. The unique new binary is pinned after build
and checked again before collection.

Across v1 and v2, the ceilings are 160 charged native applications and 180 native
seconds, with one shared 30-second analysis allocation (210 seconds combined).
The v1 failed collection's observed count remains unknown and its 80-call,
60-second charge is preserved. Static startup-path evidence of zero calls does
not give ledger credit. No neural forward, update, numerical fit, paid job,
opponent game or deployment is authorized by this harness.

Portable fixtures and tests exercise scientific equivalence, exact token
metadata, unique binary identity, zero physical Shields, accounting boundaries,
resource limits, binary provenance and cleanup failure. They execute no native
constructor, subprocess, compiler or model.
