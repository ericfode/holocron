# New binding-transfer native allocation

This is a new, separately linked build/collection route. It uses the unchanged
validated scientific source (`6355cde9…`) and the exact 26-world plan
(`0187415c…`). Only a distinct executable wrapper and Cargo target are added:
`binding-transfer-next-native-collector`. The failed normal collector and the
successful fixture-validator binaries are strict before/after byte pins.

The default supervisor command performs read-only preflight. Execution requires
root's frozen new configuration and GO. One build stage has 15 seconds; one native
stage has 30 seconds and at most 48 applications, with the original per-world
bounds. The new accounting module owns one shared serial lease and durable
reservations. Neither earlier ledger is changed or credited. Historical 160
charged applications remain charged; the new explicitly authorized ceiling is
208. The completed zero-application fixture diagnostic is separately linked.

Before native completion can admit later work, the guard requires all 26 roots,
full frozen-plan equality, actually offered source/target commits, settled final
endpoints, exact raw/journal action-state chains and per-world/global application
bounds. Missing or failed journals retain the conservative failed reservation.
Data conversion and learned-support qualification are separate subsequent gates.

All cards and the native Shield constructor-support definition remain whole and
unchanged. No physical Shields, hidden draw order or opponent-private cards are
introduced. This preparation runs no engine, model, optimizer or paid job.

Prior validated Cargo and source bytes were preserved before adding the wrapper
under `experiments/binding-transfer-v2/prelaunch-validated-source/`.
