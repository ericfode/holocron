## Shortcuts and scaling that the design permits

1. **The bag is algebraically redundant.** `supported_transition_data.py:270` supplies exactly one copy of the queried program. `train_structured_transition.py:243` computes `queried = programs[query]` and `bag = (counts / 60) @ programs`. Thus every fitted and validation row has `bag = queried / 60`. The first prediction layer can combine their weights into `W_query + W_bag/60`; no independent deck effect is identifiable. Do not force a deck effect onto immediate action outcomes that do not depend on the rest of the deck. A separate deck claim needs genuinely different multi-card original/remaining contexts and appropriate future-choice targets.
2. **A fixed wrong-program permutation is invertible.** `make_banks` at line 140 swaps the same two programs consistently in every batch and partition. With both IDs familiar, a model can learn the reverse mapping. Good or bad performance under that control does not establish reusable semantics.
3. **Input scale is not matched by parameter count.** Saved `*-golden.npz` token masks contain 48 / 28 active typed tokens for the correct arm and 1 / 1 opaque tokens for ID-only; wrong IR reverses 28 / 48. All use a fixed sum divisor 64, followed by a shared known-status vector (`encode_program_bank`, line 226). Program size can affect amplitude and act as an identity cue. This is a code-and-buffer fact; the separately bounded diagnostic below measures actual post-fit sensitivity.
4. **Context can proxy identity and mechanism.** Valid chosen targets are units for one focal ability and bases for the other; their public type, HP, owner and damage enter the 19 features. Source exhaustion and ready-resource count explain much availability. These are valid public inputs, but a context-only fitted control is needed to determine whether program information adds anything.
5. **The supervised outcomes hardly vary.** Damage is always one, exhaustion always true, reuse always false. Loss reduction can learn constants and availability rules without learning effect quantities, opposite effects, order, or program composition. Object-key invariance and order-sensitive input wiring remain structural checks; they are not native evidence of sequence semantics.

## Smallest useful next evaluation

Freeze a manifest before collection, using existing whole-card runtime admissions and actual supported bindings. The inventory owner reports 41 activated abilities on 40 admitted cards; that is source inventory, not a claim they all bind or execute. A small set with shared target domains and differing damage/heal, ready/exhaust, costs or literal quantities is more informative than a long heterogeneous list. Candidate count is not an admission gate: retain a smaller supported experiment and narrow its claim if some bindings fail.

**Unit of contrast:** run two real, unmodified native programs against the same canonical public state and same candidate target. Include cases where their legal-use/target masks or settled deltas differ. Keep a valid alternative target where necessary so a negative chosen-target example is actually observable. Use native masks, actual costs and settled counters; never fill an unexecuted future transition with a known zero. For effect contrasts, compare coordinates known under both actual commits. Program swaps against unchanged labels are sensitivity probes, not new counterfactual training truth.

**Splits:** canonical identity/reprint groups and exact normalized semantic-program duplicates are indivisible. Hash the normalized AST with sorted object keys while retaining semantic fields, costs, quantities, predicates, targets, list indices and effect order; remove only audited provenance fields such as a nonsemantic root title. Hold out public-state scenario families globally across all programs, aliases, target choices, cancel/commit/follow-up branches and cosmetic instance renamings. Reject exact encoded and canonical state overlaps across fit/evaluation. The primary score is the intersection of held-out identity/program groups and held-out state families. Seen-program/new-state results may be a separately named diagnostic. A new ID with an identical training program is duplicate-program transfer, not novel-program generalization.

**Modest engineering support target:** preferably at least four distinct training program groups and two distinct held-out groups, with each held-out group tested on at least four distinct canonical state groups. Ensure every primitive used by a held-out program has training support if the claim is recombination rather than unseen-effect extrapolation. Require at least two actual differing native contrast pairs per claimed mechanism. For a binary head promoted into the primary macro score, seek at least four known positive and four known negative outcomes per scored partition, spread over state groups; for a continuous head, at least two observed quantities and more than one state group per quantity. Report the actual support and number of clusters. These small thresholds make an engineering contrast interpretable; they do not provide a statistical power guarantee, require expanding engine coverage, or block a narrower diagnostic.

**Objective and readout:** predeclare physical scales for continuous quantities and an equal-head training objective, with equal-class averaging for supported binary heads using training data only. Keep constant or unsupported heads as explicit diagnostics rather than letting their easy observations dominate the score. Report per-head balanced accuracy and Brier/error, continuous MAE in original units, and macro averages first across state groups and then program groups. Make the paired native contrast error, `|(prediction_A - prediction_B) - (native_A - native_B)|`, a primary program-use diagnostic on common known coordinates. Give every mechanism equal weight; print denominators and ties. Do not treat multiple target slots, checkpoint evaluations or repeated batches as independent samples. Keep fixed steps and seeds, and inspect a final untouched partition once.

**Controls and scale checks:** use matched context-only, opaque-ID and correct-IR fits with identical batches, parameter budget and optimization. On unseen IDs the opaque control must use a fixed unknown representation, not fit a held-out embedding. Add program neutralization and same-state program substitution at inference; compare them to the actual native contrast and keep state fixed. A predeclared training-time permutation can remain a memorization control, but is insufficient alone. Normalize program/query activation scale consistently across arms and log pre/post-normalization RMS; if using token means, retain explicit structural length/count information and ordered paths rather than accidentally deleting multiplicity. Remove or neutralize the redundant one-source bag for this action-semantic experiment. A later deck experiment must vary the bag independently of the queried program.

The smallest run should report no embedding-distance, held-out-card retrieval or playing-strength claim. Those require their own independent common-state behavioral profiles and adequate distinct candidate programs. Freeze source, duplicate groups, state groups, masks, objective, controls, exact budget and success criteria before launching; append failures and partial support honestly. This review authorizes no collection or fit itself.
