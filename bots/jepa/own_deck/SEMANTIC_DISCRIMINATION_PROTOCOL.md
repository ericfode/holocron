# Incremental program-information experiment

This protocol is frozen before new native outcomes. Production remains unchanged.
The corrected C1R1 public-input pipeline is the baseline. The question is whether
learning the whole program adds useful held-program behavior beyond printed
metadata, a frozen random program representation, TRAIN card IDs and public state.

## Diagnosis and limits

The preceding experiment established narrow benefits from public aspect counts
and a lawful declared-target relation. It did not establish learned semantics:
ID-only won the LOF_053 comparison in all three seeds, and the frozen untrained
encoder won both held stat variants in seed 29. Printed upgrade magnitudes and
the intended-host relation make those small tasks solvable without learning
general program meaning. A frozen encoder is an informative random feature map.

The actual corpus has 115 admitted identities, 635 copies and 27 deck lists
(251 identities and 1,432 copies before admission). All 115 complete printed
profiles are unique, even with set-valued fields sorted. Therefore the proposed
comparison measures empirical incremental IR value; it cannot prove printed
metadata is insufficient or eliminate metadata fingerprints. Earlier held
results informed this design; this is a new fit with no reused learned weights,
not a claim of never previously examined cards.

## Native labels and privacy

All fixtures must pass zero-application construction, chronology and snapshot
round-trip validation inside the native stage before its first application.
Only pinned native legal menus and actual before/after public observations
produce labels. No IR-evaluated labels, inferred counterfactual outcomes or
zero-filled unknowns are allowed. Removed/zone movement is observed separately;
departed-unit numerical deltas are unknown. Include public base endpoints.

An offered intended target is committed exactly as declared. A native Cancel
may be used for an unavailable intent only when actually offered. Mandatory
on-play prompts can lack Cancel: such a root ends at the complete observed
prompt as `unoffered-observation-only`, with known false target membership and
all future/effect labels unknown. Never substitute a different target. Absent
target prompts cannot imply negative eligibility. Every root needs a validated
typed terminal; all legally committed actions must settle. Terminal categories,
applied actions, errors and unknown masks are reported explicitly.

Both decks and the opponent hand are empty in every authored capture. Features
use public BEFORE state, public static definitions and lawful declared intent;
only the own source card may be in hand. Draw order, opponent private identities,
native menus, future observations and commitment outcomes are not model inputs.
The eight-role projection must contain complete arena membership for known
aspect counts. No missing Jedi, upgrade-presence or hand-count feature is added.

## Matched model and controls

Reuse the corrected C1R1 context32/candidate43 input and common graph: card,
context and candidate embeddings of width16, source80->32->9 and branch80->32->7.
All five arms use seeds 17, 29 and 43, cloned per-seed initial tensors, the same
full-TRAIN batch order, masks, loss, TRAIN-only transforms and 200 updates:

1. Learned full typed program.
2. Frozen full typed encoder with trained heads.
3. Learned PRINTED-only bank: exact complete printed fields retained; abilities,
   keywordValues and attachCondition masked in the same full-bank structure.
4. TRAIN-ID lookup, with held identities/equivalent programs mapped to UNK0.
5. Public-only: zero semantic vector with the same allocated graph.

All held aliases/program groups are excluded from TRAIN observations and
numeric scaling. Public held syntax may allocate symbols before labels;
held-only atoms receive no observation gradient from TRAIN examples and must be reported. Dense
AdamW weight decay can still shrink unused embedding rows; this is not training
on held labels. PRINTED-only uses the common vocabulary and
TRAIN numeric scale. Actual consumed-input hashes must describe each arm's
masked/zero/ID representation, rather than hash the full IR for every arm.

After final normal evaluation, one additional evaluation per arm/seed swaps
only abilities, using a frozen cyclic donor map within TRAIN and within HELD.
Source printed fields, keywordValues and attachCondition stay byte-exact.
No wrong-program training arm or adaptation is performed. Printed/ID/public
predictions must be identical under that intervention. A separate predeclared
IR-sensitivity diagnostic passes only if swapping worsens learned-full primary
MAE in each held group/seed and by at least 10% per group after pooling seeds.
If correct pooled error is zero, relative worsening is undefined and unsupported.
Frozen-full changes are descriptive. This diagnostic is separate from the
primary all-control gate and is not sufficient evidence of correct semantics;
failure prevents an IR-sensitivity claim.

## Primary readouts and decision

Report initial/final TRAIN, state-held, program-held and jointly held metrics
for all 16 heads and every arm/seed. These and auxiliary conditional/quantity
stress tests are descriptive. Always use observed known masks.

ASH_081 primary error is root-balanced signed target-damage MAE on physical
anchors A/B. IBH_104 primary error is the equal-head mean of root-balanced
target-allowed and removal MAE on anchors A/B only. Keep the two held-program groups separate;
do not pool healing units with binary eligibility units. Include both held
state partitions. Zero, TRAIN-mean and one fixed public-input ridge design
(lambda 1, 16 attempted head fits) are the simple baselines.

The narrow learned incremental-IR gate requires lower primary MAE than each of
PRINTED-only, frozen-full, ID-only, public-only and every simple baseline for
each held-program group in each seed. It also requires at least 10% relative
error reduction separately for every group/control after summing the three
seed errors. A zero comparator makes relative reduction undefined, not passed.

The predeclared eligibility interaction is
`D=(allowed(A)-allowed(B))_IBH104-(allowed(A)-allowed(B))_LOF077`.
Native D must be -2 in world0 and +2 in world1. Learned D must have both correct
signs in every seed. This is an eligibility/intent contrast, not two legal
action outcomes. The exact public-input witness concerns context32 plus each
particular anchor43 as consumed by the branch, not the complete candidate bank.
The source candidate's printed data may differ between cards.

Report action ranking separately on the predeclared ASH_081/world1 intent pair:
utility is minus the sum of anchor A/B damage deltas for each actual action.
Require both legal actions committed, complete anchor masks and a non-tied
native utility. The descriptive threshold is accuracy >=0.75 in each seed;
with one non-tied pair this requires the correct rank in every seed. World0
has tied native healing and is excluded. If the preconditions fail the ranking
is unevaluable. Never count invalid intents as action ranking or infer an
unexecuted action's outcome. This diagnostic is separate from the primary gate.

Only two held program groups are tested, with nested public states and three
training seeds. Checks, heads, repeated roots and seeds are not independent
semantic-family trials. Failure or mixed results remain visible. A pass would
support only this incremental IR assay; `semantic_validated=false` and no
playing-strength claim or production change follow.
