# Synthetic elementary native collector

Source only until the coordinator freezes a new allocation and authorizes it.
No engine, catalogue, compiler or existing collector source is modified.

Invocation: `compositional-typed-native-collector PLAN NEW_RECEIPT NEW_JOURNAL`.
The outputs are exclusive. The complete plan contains 32 synthetic event
definitions and six synthetic vanilla anchor definitions. Runtime input status
`supported` is explicitly not compiler or actual-card certification. Exact
reviewed Shield support and unchanged base/leader/resource rows are retained.

Each root contains sixteen public units and only its own known event in hand.
Both decks and opposing hand/resources remain empty. The native program must
admit every definition and round-trip all 128 fixtures before its first apply.
These operations are inside the same 30-second native invocation. Every apply
has a durable fsynced intent and an after/error record; the limits are four per
root and 512 globally. The direct simple-event path is expected to use two per
root, but only measured journal counts become actual exposure.

The only action policy is own-hand Play followed by its declared single target.
If unoffered, use an actual native Cancel; if absent, retain prompt-only unknown
futures. No substitute, optional effect, upTo/Done or unrecognized continuation
is executed. Errors and incomplete roots stop the collection. Actual menu
membership and native snapshots supply labels; the plan's arithmetic is only
predeclared design, never an oracle used in place of native observations.

The board has two cost-2 units per owner/arena, one cost-3 and one cost-4. All
have synthetic HP10/power0. A healthy intended unit retains another wounded
eligible twin, preventing a global no-effect heal skip. Actual healthy-menu
membership, paid settlement and zero change must still pass data admission.
The held split is parity of five program-factor bits. This tests synthetic
combination transfer, not unseen rules, real cards, decks or playing strength.
